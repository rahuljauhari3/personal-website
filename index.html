Flagship project

vLLM multi-instance benchmarking infrastructure

Built a repeatable way to test how many user requests a CPU system could serve by running multiple isolated vLLM containers in parallel, each pinned to its own CPU core range and loading its own model instance.

Problem
One model server did not show whether a CPU machine could serve more users by splitting traffic across multiple isolated instances.
Build
Podman containers for each vLLM instance, explicit CPU core ranges per container, per-instance model loading, nginx load balancing, shared model cache, and offline-by-default execution.
Impact
Made request routing and capacity testing reproducible, while making memory, scaling, and CPU-affinity issues easier to isolate.

vLLM multi-instance benchmark infrastructure

Situation
A single LLM server could not show how many user requests the CPU system could handle under parallel serving.
Task
Create a repeatable multi-instance setup to serve more requests, compare configurations, and expose regressions.
Action
Built containerized vLLM instances with Podman, pinned each instance to a CPU core range, and routed user requests through a load balancer.
Result
Showed how request capacity changed across isolated instances and helped root-cause memory, scaling, and CPU-binding issues.
